# Project Roles & Development Philosophy

This project follows a multi-disciplinary approach to software engineering. Below is the breakdown of the roles played during the development of the Usher Management System:

### 1. The Business Analyst (BA)
*   **The Task:** 
    Translating real-world ministry needs (like the "Sunday Rule" and birthday reporting) into "Functional Requirements."
*   **The Evidence:** 
    `docs/11-backend-implementation-logic.md`

### 2. The Systems Architect
*   **The Task:** 
    Designing the "Blueprint" and ensuring the system is organized, scalable, and resilient to change.
*   **The Evidence:** 
    The folder structure, `models.py` schema, and the `RESOURCES.md` dependency mapping.

### 3. The Project Manager (PM)
*   **The Task:** 
    Managing scope, setting the pace, and ensuring "Quality Control" through consistent file headers and documentation audits.
*   **The Evidence:** 
    Systematic "Spring Cleaning" of file headers and phased implementation strategy.

### 4. The Backend Programmer
*   **The Task:** 
    Turning blueprints into a working engine using Python, FastAPI, and SQLAlchemy.
*   **The Evidence:** 
    Implementation of `json.dumps` for audit snapshots and all API logic in the `routers/` directory.

---

**Current Designation:** Full-Stack Developer & Technical Lead
